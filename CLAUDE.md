# CLAUDE.md — Markscope

Markscope is a Manifest V3 browser extension (Chrome/Edge; Firefox experimental) that renders Markdown
as a fast, secure, navigable document. TypeScript (strict), no UI framework, bundled with esbuild.

## Commands

```bash
npm install
npm run dev              # watch build → dist/chrome (load unpacked)
npm run build            # dist/chrome   |  npm run build:firefox → dist/firefox
npm run typecheck        # tsc --noEmit (TS 7)
npm test                 # Vitest unit + integration (jsdom)
npm run test:coverage    # thresholds: 80% lines/funcs/statements, 75% branches
npx playwright install chromium   # once
npm run test:e2e         # Playwright drives the REAL extension (build first!)
npm run build:vscode     # dist/vscode: the VS Code extension  |  npm run package:vscode → release/*.vsix
npm run typecheck:vscode # the VS Code entry points without chrome types
npm run test:vscode:webview  # webview in Chromium with a fake host (build:vscode first)
npm run test:vscode      # extension in a real VS Code (builds, downloads VS Code once; VSCODE_TEST_VERSION=1.90.0 for the oldest engine)
npm run release          # typecheck + tests + both builds + release/*.zip + SHA256SUMS
node scripts/screenshots.mjs      # store screenshots + promo tile (after build)
node scripts/icons.mjs            # rasterize src/icons/logo.svg → icon-*.png
npx prettier --write …   # semi:false, singleQuote, printWidth 90
```

E2E always runs against `dist/chrome`: rebuild before `npm run test:e2e`.

GitHub: <https://github.com/AbdallahSaeed/markscope>. Website: <https://abdallahsaeed.github.io/markscope/>, built by `scripts/build-site.mjs` from `site/` + `docs/PRIVACY.md` + store screenshots.

Workflows in `.github/workflows/`:

- `ci.yml`: typecheck, prettier, coverage, both builds, `web-ext lint`, E2E.
- `pages.yml`: deploys the website.
- `release.yml`: on tag `vX.Y.Z` (must equal `package.json` version), creates the GitHub Release with the zips and a source zip. The store jobs run only if `CHROME_*` / `AMO_*` secrets exist.

## Architecture (where things live)

| Context | Entry | Notes |
| --- | --- | --- |
| Content script | `src/content/index.ts` (+ pure `detect.ts`) | ~6 KB. Reads `<pre>` text of plain-text `.md` pages, hands it off. **Never renders.** |
| Service worker | `src/background/index.ts` | Thin wiring. Logic is in `router.ts` (validated messages + sender checks), `handoff.ts` (one-time text handoff in `storage.session`), `ai-service.ts` (AI over a Port), `content-scripts.ts`, `context-menus.ts`. |
| Viewer page | `src/viewer/index.ts` → `viewer.html` | `app.ts` orchestrates (keep < 800 lines). It delegates to `document-view.ts` (sanitized DOM and decorations), `sidebar.ts`, `files-panel.ts`, `folder-controller.ts` + `folder-session.ts` + `workspace.ts` (Open folder), `save-actions.ts`, `document-actions.ts` (print/export), `navigation.ts`, `search-bar.ts`, `palette.ts`, `ai-panel.ts`, `commands.ts` (shortcuts, menu, palette items), `editor/` (CodeMirror 6 behind `EditorAdapter`; `editor-controller.ts` lazy-loads `codemirror.ts` on first Edit view), `split-view.ts` (scroll sync via `editor/scroll-map.ts`, jump to source, cursor highlight), `split-divider.ts`, `status-bar.ts`, `live-reload.ts` (polling and disk-change conflicts), `merge-dialog.ts` (compare; lazy `editor/merge-view.ts`), `drafts.ts` + `draft-restore.ts` (crash backup). |
| Render worker | `src/engine/worker.ts` | `engine/render.ts` is pure (markdown-it + plugins + hljs + KaTeX). `RenderClient` uses the worker above 64 KB. |
| Shared | `src/shared/` | `settings.ts` (schema + `parseSettings` validation), `urls.ts` (URL policy: links, media, viewer URLs, `workspace://`), `messages.ts`, `dom.ts` (`h()` helper, no innerHTML), `icons.ts`. |
| Storage | `src/storage/` | Settings in `storage.sync`, library in `storage.local`, AI key in local/session **bound to its endpoint origin**. Local docs, opened folders and unsaved-edit backups (`viewer/drafts.ts`) are in IndexedDB (`viewer/idb.ts`, schema v3). |
| VS Code extension | `src/vscode/` | Host (`extension/`: `preview-manager.ts` (also the Reader custom editor and Export HTML), `preview-panel.ts`, `link-policy.ts`, `confine.ts`, `html.ts` CSP), webview (`webview/`: `preview-app.ts`), `protocol.ts`, `config-schema.ts`. Built by `scripts/build-vscode.mjs`; the manifest is generated by `scripts/vscode-manifest.mjs`. Plan and status: `docs/VSCODE-PLAN.md`. |
| Pages | `src/pages/*.html`, `src/popup`, `src/options`, `src/styles` | `styles/tokens.css` is the design system (OKLCH); `document.css` is also inlined into HTML exports. |

The manifest is generated by `scripts/manifest.mjs`. Content-script match patterns come from
`markdownMatchPatterns()` in `src/shared/urls.ts`, so the build imports a `.ts` file
(Node strips the types).

## Security invariants (do not regress; tests cover them)

- All rendered HTML goes through `engine/sanitize.ts`.
  - No script, style, form, iframe, object, embed, `on*` attributes, `srcdoc`, `poster` or `xlink:href`.
  - Inline `style` is allowlisted (no `url()`, `var()`, position or z-index).
  - Viewer ids (`ms-root`, `ms-tab-*`, …) are reserved.
- Diagram SVG is sanitized in `viewer/diagrams.ts`. Mermaid's `<style>` is kept only if every rule is scoped to the diagram id and any `url()` is a local `url(#…)`.
- Link and media URLs go through `resolveLink` / `resolveMediaSrc`. `file:` is only allowed from `file:` documents. `workspace://` paths clamp `..` at the folder root.
- Router: a content script may only hand off **its own top-frame URL**. Privileged messages require an extension-page sender.
- AI:
  - The key is never sent to pages.
  - It is withheld if `ai.baseUrl`'s origin changed.
  - Remote endpoints must be https (http only for localhost).
  - Settings imports never import `ai.*`.
  - Remote media in AI output are never loaded.
  - `</document>` breakouts are neutralized.
- The extension-page CSP is `script-src 'self' 'wasm-unsafe-eval'` (no inline script). The HTML export carries `default-src 'none'` and makes no external requests.
- VS Code (see `docs/SECURITY.md`):
  - The webview is untrusted: every message goes through `parseWebviewMessage`, and the host acts on validated data, never on a field that says what to run.
  - The webview names files only by a folder-relative path; the host confines it to the root it chose and checks the real path (symlinks).
  - `enableCommandUris: false`; only `http`, `https`, `mailto` and `tel` reach `env.openExternal`; the CSP has no `unsafe-eval` and no remote script or `connect-src`.
  - AI: `markscope.ai.*` are `application`-scoped; requests run in the host (`ai-host.ts` over `src/ai/service.ts`); the key lives in `SecretStorage` bound to its endpoint origin and is never sent to the webview; the assistant is forced off in untrusted workspaces (`config.ts`).
- Host access: Chrome grants it **per origin** from the `*.md` content-script patterns, which is effectively all sites. Document this honestly; don't claim tighter scoping.

## Conventions

- Strict TS, explicit types on exports, `unknown` + narrowing for untrusted data, immutable updates (`{ ...obj }`).
- Build UI with `h()` from `shared/dom.ts`, never `innerHTML`. The only exception is `source-view.ts`, which inserts highlight.js output generated from text.
- Keep files under 800 lines; extract modules (see how `app.ts` was split).
- Every user-visible change needs a unit or integration test, and an E2E test for flows.
- Conventional commits (`feat:`, `fix:`, …), ending with the `Co-Authored-By` trailer the environment specifies.
- Update `CHANGELOG.md`, `README.md`, `docs/QA-CHECKLIST.md` and `CHROMEWEBSTORE.md` when behavior or permissions change.

## Gotchas learned the hard way

- **E2E browser:** branded Google Chrome (137+) ignores `--load-extension`. Use Playwright's Chromium (`channel: 'chromium'`).
  - In that profile, "Allow access to file URLs" is already **on**; clicking the toggle turns it off.
- **Clipboard:** permissions can't be granted to `chrome-extension://` origins in automation. Stub `navigator.clipboard.writeText` in the page.
- **Native pickers** (`showOpenFilePicker`, `showSaveFilePicker`, `showDirectoryPicker`) can't be driven headlessly.
  - Mock them in the page, re-installing after any navigation.
  - For **real** handles, use OPFS (`navigator.storage.getDirectory()`). Its handles are structured-cloneable into IndexedDB and always granted. See `tests/e2e/folder.spec.ts`.
- **Large-DOM tests:** Playwright tracing serializes the DOM on every step and hangs on 48k-line docs. Large-document tests use `trace: 'off'`.
- **Failure screenshots** often capture the context's initial `about:blank` page. To see the real state, write a throwaway probe spec or script that screenshots explicitly.
- **File and folder handles** lose permission on page reload ("not allowed by the user agent…").
  - Use `readIfPermitted` / `ensurePermission` from `viewer/file-access.ts`; requesting permission needs a user gesture.
  - This is why folder navigation is **in place** (`history.pushState`), not a reload.
- **Editor debounce:** edits reach `doc.source` through a 160 ms debounce in `EditorController`. Anything acting on the source right away must handle it: Save calls `commitEditor` first (it reads `app.editor.value`), and Discard calls `editor.cancelPending()`. `savedSource` holds the last loaded or saved text.
- **Editor text changes:** use `editor.setValue(text)` (a CodeMirror transaction, so ⌘Z still works) and pass `{ resetHistory: true }` only when a different document opens. `setValue` never fires `onChange`.
- **Editor E2E:** CodeMirror's content is a contenteditable `.ms-editor .cm-content`: use `fill`/`toHaveText`, not `toHaveValue`. Use `ControlOrMeta+…` for CodeMirror keys (it binds ⌘ on macOS).
- **Editor key bindings:** on macOS, CodeMirror matches ⌥-only combinations by the typed character (⌥⇧F arrives as "Ï"), so bindings like `Shift-Alt-f` never fire there. Include `Mod` in any Alt binding. Add formatting commands to `editor/keymap.ts` only; the CodeMirror keymap, shortcut help and palette all read it.
- **Disk conflicts:** live reload polls also while there are unsaved edits; a change then goes through `LiveReload.showConflict` (Keep mine / Load theirs / Compare), never straight into the editor. Save does the same check against `doc.lastModified`. "Keep mine" and Compare make the disk version the new `savedSource`/`lastModified` baseline, so the next Save doesn't ask again.
- **Merge view:** `@codemirror/merge` re-renders its revert arrows on mousedown, so a `click` listener never fires for them. React to changes with an `EditorView.updateListener` on the editable side.
- **Scroll sync echoes:** `split-view.ts` tells its own scroll echoes apart by comparing the pane's `scrollTop` with the value it just set, not by a time window. A time window drops real user scrolls that land right after a sync (this flaked the E2E test).
- **Editor pane height:** the split pane needs `min-height: 0`, otherwise the grid row grows to CodeMirror's full content height and the editor spills under the status bar.
- **Mermaid 12:** use the **root-level** `htmlLabels: false`; `flowchart.htmlLabels` is ignored, and its foreignObject labels get stripped.
- **KaTeX:** `package.json` `overrides` pins Mermaid's nested KaTeX to ours (security advisory). Keep it when upgrading.
- **Print:**
  - Dark tokens apply to `@media screen` only, so paper is always light.
  - ⌘P goes through `printDocument` (re-renders Mermaid light); the browser menu's print cannot await.
- **Grid layout:** `.ms-shell` regions have pinned `grid-column`s. Hiding one with `display: none` must never reflow the others; that was the focus-mode collapse bug.
- **Scrolling:** `Element.scrollIntoView` scrolls every ancestor, including the window. For the sidebar, scroll the panel manually (`revealInPanel`).
- **Scripted edits:** Prettier reflows long lines. A scripted find-and-replace must match the formatted text; otherwise use the Edit tool after reading the file.
- **VS Code webview:**
  - `acquireVsCodeApi()` can be called once. The page's own URL is not the extension's folder, so assets come as webview URIs in `init` (worker, KaTeX CSS); never rely on relative URLs there.
  - The render worker must run from a `blob:` URL (`worker-src blob:`). Don't add another `Worker` path.
  - Lines are 1-based in the protocol and the viewer; VS Code's are 0-based. Convert only in the host.
  - Scroll echoes are told apart by value (`webview/scroll-echo.ts`, and `lastRevealedFromPreview` in the panel), as in `split-view.ts`. Don't add a time window.
  - The sanitizer strips `command:` and `vscode:` hrefs, so those links are inert anchors (no `ms-link-invalid` class).
  - The webview can't be inspected from the host. Integration tests (`tests/vscode/integration`) observe it through diagnostics; DOM behavior is covered by the harness (`tests/vscode/harness`) against the real CSP.
  - `tsconfig` has `allowImportingTsExtensions` because `config-schema.ts` is imported by Node (the manifest script) with `.ts` paths and no `@/` aliases.
- **PDF review:** there's no poppler here. Rasterize with a small Swift PDFKit script to inspect print output visually.
